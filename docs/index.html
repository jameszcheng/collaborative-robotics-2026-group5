Overview

Problem Statement

Household and laboratory environments contain objects that constantly need to be retrieved, reorganized, or moved on demand. A robot that can understand natural spoken commands and autonomously execute multi-step manipulation tasks—locating, navigating to, and grasping objects—would be a meaningful real-world collaborator.

We built a fully integrated pipeline on the TidyBot2 platform: a holonomic mobile base with two 6-DOF WX250s arms, an Intel RealSense D435 depth camera on a pan-tilt mount, and an onboard Intel NUC running ROS2 Humble.

🗣️

Task 1 — Object Retrieval

User says "retrieve the banana." Robot detects the object with YOLO, navigates to it, grasps it with the right arm, and returns to the starting position while holding the object.

📦

Task 2 — Pick and Place

User says "pick up the banana and place it in the bin." Robot detects, navigates, grasps, then drops the object 25 cm to its right—into a bowl or bin positioned beside the robot.

🤖

Task 3 — Bimanual Pillow Retrieval

Robot detects a red pillow using an HSV-based color detector, navigates to it, and performs a coordinated two-arm grasp to pick it up — demonstrating bimanual manipulation for large or deformable objects a single arm cannot reliably handle.

Core challenge: Bridging the gap between noisy real-time perception (depth sensor uncertainty, YOLO false positives) and reliable robot action (navigation accuracy, successful grasping) in an unstructured tabletop environment— all triggered by a single natural language utterance.
Method

System Architecture

The system is composed of four specialized ROS2 nodes orchestrated by a central coordinator. Each node has a single responsibility; the coordinator sequences them via topics and state transitions.

task1_coordinator.py tidybot_bringup/scripts/ Task 1 state machine — detect → navigate → pick up → return to start
task2_coordinator.py tidybot_bringup/scripts/ Task 2 state machine — detect → navigate → pick up → drop in bowl/bin

Coordinator State Machines

Each task has its own coordinator with a dedicated finite state machine. States share a common pattern; the key difference is Task 1 adds a RETURNING state to drive back to the start, while Task 2 ends immediately after the drop.

Any state can transition to FAILED on timeout, which sends an e-stop and resets to IDLE.
IDLE

Waits for a voice command from the Gemini NLP node (/nlp/response) or a manual string trigger on /coordinator/start. Ignores new triggers while a task is in progress.

SEARCHING (timeout: 30s)

Publishes the target label to the YOLO detector. Collects 3 confident detections (≥0.4 confidence), averages their x/y to form a stable navigation goal, then publishes it to the navigator. Averaging multiple frames prevents wrong-direction drives from single noisy depth readings.

NAVIGATING (timeout: 90s)

Waits for /coordinator/nav_complete from navigate_to_object.py. The robot drives to a standoff ~0.4m in front of the object and aligns yaw. On arrival, the coordinator tilts the camera down (0.0 pan, 0.5 rad tilt) and transitions to PAUSE.

PAUSE

A configurable settling delay (default 3 s) that lets the robot stop moving and stale perception data age out before pickup is triggered. No signals are sent; the coordinator simply waits.

PICKING_UP (timeout: 120s)

Publishes an Empty trigger to the pickup node and waits for success/failure.
Task 1 (task1_pickup.py): APPROACH → DESCEND → GRASP → LIFT — holds the object at lift height.
Task 2 (task2_pickup.py): APPROACH → DESCEND → GRASP → LIFT → DROP — moves arm 25 cm right and releases into bowl/bin.

RETURNING (Task 1 only · timeout: 120s)

Publishes /coordinator/return_to_origin. The navigation node drives the robot back to the saved start position (0, 0). Transitions to DONE when nav_complete arrives.

DONE / FAILED

DONE logs success, waits 2 s, returns to IDLE. FAILED publishes a zero-velocity e-stop to /cmd_vel and returns to IDLE immediately.

Node Details

🎯 Perception Node

Runs YOLOv8 on every RGB frame. For each detection, samples a 21×21 depth patch around the bounding box center and takes the median (robust to sensor noise). Back-projects pixel + depth into the camera optical frame, then transforms to base_link via the TF tree. Publishes pose and confidence per frame.

🧭 Navigation Node

Receives the coordinator's pre-averaged goal. Computes a standoff position 0.4m behind the object with a 0.15m lateral offset (right-arm centering). Uses a proportional controller (50 Hz): drive to standoff, then rotate in place to align yaw within 5°. Locks odometry origin at startup to avoid drift.

🦾 Arm / Pickup Nodes

Two separate pickup nodes using the mink IK library with top-down grasps.
task1_pickup: 4 phases — APPROACH (10 cm above) → DESCEND (2 cm above) → GRASP → LIFT (25 cm up). Holds object.
task2_pickup: 5 phases — same start, adds DROP: moves arm 25 cm right and opens gripper. Includes internal camera sweep for close-range re-detection.

🗣️ NLP Interface

Records audio, transcribes via SpeechRecognition, and passes the text to Google Gemini. Returns structured JSON {action, object, target}. The object label is published at runtime to dynamically configure the YOLO detector—no code changes needed per object.

Camera Sweep in Task 2 Pickup

If the object is not immediately visible at the standoff position, task2_pickup.py internally sweeps the pan-tilt camera across 6 positions before declaring failure. The sweep uses the same fixed angle at which the first confident detection arrives—preventing cross-angle depth mixing artifacts: 

  Position 1: pan= 0.0,  tilt=0.5  (center, looking down steeply)
  Position 2: pan= 0.0,  tilt=0.3  (center, shallower)
  Position 3: pan=-0.3,  tilt=0.5  (left)
  Position 4: pan=+0.3,  tilt=0.5  (right)
  Position 5: pan=-0.3,  tilt=0.3  (left, shallower)
  Position 6: pan=+0.3,  tilt=0.3  (right, shallower)

Perception Strategy: SEARCHING + PAUSE

SEARCHING — Navigation Goal

Collects 3 confident YOLO detections from 1–2 m away and averages their x/y. Single-frame depth at distance is noisy; averaging prevents wrong-direction navigation while keeping the robot responsive.

PAUSE — Settling Before Pickup

A 3-second delay after navigation lets the robot stop moving and stale detection data age out. The pickup node waits for a fresh detection after this window—ensuring the arm target comes from a stationary robot pose.

Quick Start

# Clone the repo
git clone https://github.com/jameszcheng/collaborative-robotics-2026-group5.git
cd collaborative-robotics-2026-group5

# Build
cd ros2_ws && source /opt/ros/humble/setup.bash && colcon build

# Terminal 1 — Robot hardware + motion planner
source setup_env.bash
ros2 launch tidybot_bringup real.launch.py use_planner:=true

# Terminal 2 — Task 1: pick up and return to start
ros2 launch tidybot_bringup task1.launch.py

# Terminal 2 — Task 2: pick up and drop in bowl/bin
ros2 launch tidybot_bringup task2.launch.py

# Manual trigger (no voice needed)
ros2 topic pub /coordinator/start std_msgs/String "data: apple" --once
