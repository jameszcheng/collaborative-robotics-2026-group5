Overview

Problem Statement

Household and laboratory environments contain objects that constantly need to be retrieved, reorganized, or moved on demand. A robot that can understand natural spoken commands and autonomously execute multi-step manipulation tasks—locating, navigating to, and grasping objects—would be a meaningful real-world collaborator.

We built a fully integrated pipeline on the TidyBot2 platform: a holonomic mobile base with two 6-DOF WX250s arms, an Intel RealSense D435 depth camera on a pan-tilt mount, and an onboard Intel NUC running ROS2 Humble.

Method

System Architecture

The system is composed of four specialized ROS2 nodes orchestrated by a central coordinator. Each node has a single responsibility; the coordinator sequences them via topics and state transitions.

NodeFileRole
coordinator_node.py tidybot_bringup/scripts/ Central state machine — orchestrates all other nodes
detect_object_real.py tidybot_bringup/scripts/ YOLOv8 + RealSense depth → 3D object pose in base_link
navigate_to_object.py tidybot_bringup/scripts/ Proportional controller → standoff position + yaw alignment
pickup.py tidybot_bringup/scripts/ Arm state machine using mink IK → approach → grasp → lift

Coordinator State Machine

The coordinator implements a 6-state finite state machine. Each state has a defined timeout and a single entry/exit condition—keeping logic clean and debuggable.

IDLE
→
SEARCHING
→
NAVIGATING
→
REDETECTING
→
PICKING UP
→
DONE
→
IDLE
Any state can transition to FAILED on timeout, which resets to IDLE.
IDLE

Waits for a voice command from the Gemini NLP node (/nlp/response) or a manual string trigger. Ignores new triggers until pipeline completes.

SEARCHING (timeout: 30s)

Tells the YOLO detector what to look for. Collects 3 confident detections (≥0.4 confidence), averages their x/y to form a stable navigation goal, and publishes it to the navigator. Single YOLO frames are noisy; averaging before committing to navigation prevents wrong-direction drives.

NAVIGATING (timeout: 90s)

Waits for /coordinator/nav_complete. Upon arrival, resets all perception buffers and stamps a minimum timestamp—any pose detected while the robot was moving is discarded (TF accuracy degrades during motion).

REDETECTING (timeout: 30s)

At close range (~0.4m), collects 3 more detections—all from the same camera pan/tilt angle. If the camera moves, the buffer resets, preventing cross-angle averaging artifacts. If no object is found, sweeps across 6 pan/tilt positions. Close-range depth is far more accurate for arm planning than distant estimates.

PICKING UP (timeout: 60s)

Fires the pickup trigger and waits for the arm node to report success or failure.

DONE / FAILED

DONE waits 2s for settling, then returns to IDLE. FAILED sends an emergency stop and returns to IDLE immediately.

Node Details

🎯 Perception Node

Runs YOLOv8 on every RGB frame. For each detection, samples a 21×21 depth patch around the bounding box center and takes the median (robust to sensor noise). Back-projects pixel + depth into the camera optical frame, then transforms to base_link via the TF tree. Publishes pose and confidence per frame.

🧭 Navigation Node

Receives the coordinator's pre-averaged goal. Computes a standoff position 0.4m behind the object with a 0.15m lateral offset (right-arm centering). Uses a proportional controller (50 Hz): drive to standoff, then rotate in place to align yaw within 5°. Locks odometry origin at startup to avoid drift.

🦾 Arm / Pickup Node

Executes a 5-phase arm state machine using the mink IK library. All waypoints use a top-down grasp orientation. A −0.07m Y offset compensates for the systematic error between camera-reported position and gripper contact point. Reports success/failure to coordinator.

🗣️ NLP Interface

Records audio, transcribes via SpeechRecognition, and passes the text to Google Gemini. Returns structured JSON {action, object, target}. The object label is published at runtime to dynamically configure the YOLO detector—no code changes needed per object.

Camera Sweep During Redetection

If the object is not immediately visible at the standoff position, the coordinator systematically sweeps the pan-tilt camera across 6 positions before timing out: 

  Position 1: pan= 0.0,  tilt=0.5  (center, looking down steeply)
  Position 2: pan= 0.0,  tilt=0.3  (center, shallower)
  Position 3: pan=-0.3,  tilt=0.5  (left)
  Position 4: pan=+0.3,  tilt=0.5  (right)
  Position 5: pan=-0.3,  tilt=0.3  (left, shallower)
  Position 6: pan=+0.3,  tilt=0.3  (right, shallower)

  The moment a confident detection arrives, the sweep freezes and waits for
  the remaining samples at that exact angle (no cross-angle mixing).

Why Two Rounds of Pose Averaging?

Round 1 — SEARCHING (1–2m away)

Provides a stable navigation direction. Single-frame depth at distance is noisy, so 3 averaged samples prevent wrong-direction navigation while keeping the robot responsive.

Round 2 — REDETECTING (0.4m away)

Provides a precise arm target. Close range gives better depth accuracy. A timestamp filter discards any stale poses captured while the robot was still in motion (when TF accuracy is lowest).

# Clone the repo
git clone https://github.com/jameszcheng/collaborative-robotics-2026-group5.git
cd collaborative-robotics-2026-group5

# Build
cd ros2_ws && source /opt/ros/humble/setup.bash && colcon build

# Run the full coordinator pipeline on real hardware
source setup_env.bash
ros2 launch tidybot_bringup coordinator.launch.py target_label:=banana

System Requirements

Software

  • Ubuntu 22.04
  • ROS2 Humble
  • Python 3.10+ (uv)
  • YOLOv8, mink, mujoco
  • google-genai (Gemini)

Hardware

  • TidyBot2 holonomic base
  • 2× WX250s 6-DOF arms
  • Intel RealSense D435
  • Pan-tilt camera mount
  • Intel NUC onboard PC

Robot Specs

  • Base: 3 DOF (x, y, θ)
  • Arms: 6 DOF each
  • Reach: 650mm, 250g payload
  • Camera: RGB + Depth aligned
  • Comm: Dynamixel + CAN
